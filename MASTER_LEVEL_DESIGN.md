# Mixing Flavors: Voxel Gauntlet — Architecture

This document is the local implementation companion to the supplied GDD/TDD.

## Runtime boundaries

- `GameManager` routes application modes and owns the active mode payload.
- `PuzzleManager` loads the small deterministic runtime catalog and selects puzzles by catalog version, run seed, mode, and depth.
- `GauntletManager` owns the fixed 120-second clock, depth, streak, score, and capped banked progression.
- `SaveManager` is the authoritative profile store for shards, inventory, completion, settings, gacha pity, daily results, achievements, themes, trophies, and run history.
- `GachaService` is a pure deterministic domain service; it has no scene or rendering dependencies.
- `DailyChallengeService` derives a versioned UTC daily identity and delegates sequence selection to the existing puzzle authority.
- `AchievementService` is a pure, versioned local achievement domain service; gacha disclosure is the only gacha-related event and no achievement depends on roll luck.
- `RunHistoryService` remains a local replay/share/best-score domain service; it never becomes a second gameplay authority.
- `GridManager` owns canonical voxel state, clue projection, input transitions, undo, and MultiMesh projection.
- `EscapeGauntlet` presents the gauntlet HUD and binds the service state to the puzzle scene.

## Difficulty contract

- Depths 1–10: 3×3×3, easy tier.
- Depths 11–30: 4×4×4, medium tier.
- Depths 31+: 5×5×5, hard tier.
- Every round starts with exactly 120 seconds. Par time is scoring metadata only.
- A run seed is generated by `GameManager.begin_run()` and can be supplied explicitly for replay/testing.

## Content strategy

The complete source library remains under `assets/puzzles/` for future lazy-loaded compendium shards. The Web runtime ships `assets/puzzles/gauntlet_catalog.json`, a small validated set selected by `tools/build-puzzle-catalog.js`, so startup does not parse or solve thousands of puzzles.

## Verification contract

Every change must pass:

```powershell
godot --headless --rendering-driver opengl3 -s addons/gut/gut_cmdln.gd -gdir=res://test/unit/ -gexit
npm run build:web
$env:PLAYWRIGHT_PORT='8082'
npm test
```

The Playwright suite runs serially because the Godot JavaScript bridge has one shared callback per page and parallel workers can starve the engine during scene transitions.

The production `Web` preset excludes the test bridge; the `WebTest` preset enables the `e2e` feature for browser tests only. `npm run verify:web` scans the production PCK before release.
